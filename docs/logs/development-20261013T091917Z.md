**Decisions for the lead (A00)**, in plain words:
1. **One font a run.** The zoom keys need one owner for their commands, so the font has them. A second font node in a run now fails to load, naming `zoom in`, so a project the `ide` hosts cannot have its own font. No project has one today.
   - Other ways: a param that gives the zoom to one font (about 5 lines), or commands per view (an engine change).
   - Recommended: keep, and add the param the day a hosted project needs text.
2. **Where the `ide`'s zoom is kept**: in the library's font folder, `src/recipes/parts/font/.vulpen/font.ini`. Every app that uses the library's font shares it, and git leaves it out. Recommended: keep.
3. **A paste in the terminal runs its lines**, as a shell's does, so a copied line that ends in a line break runs at once.
   - Other ways: paste only up to the first break, or paste breaks as blanks.
   - Recommended: keep.
4. **What nodes write is not muted.** The plan said info lines muted, but a node's own lines, as the probe's values, are what a person watches, so they stay in the text color. Recommended: keep.
5. **Colors only for C++, GLSL, manifests and `.ini` files.** Python, CMake, shell and Markdown show in one color. Recommended: keep until those are edited in the `ide`.
6. **The `ide` test never copies or pastes**, since with a window that would write over the clipboard of whoever runs the tests. Recommended: keep.
7. **Scripts cannot press what shows later.** Every scripted event reaches the first frame. So a script cannot press a completion, which shows only once Tab's `complete` answers, and two presses in different parts both act in that first frame, in the wrong order. The terminal test's old "presses a completion" pressed nothing listed.
   - A command that makes a script wait for a frame would lift this; it belongs with GUI tests (H1).
   - Recommended: decide with H1.
