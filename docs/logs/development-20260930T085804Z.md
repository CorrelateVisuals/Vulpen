**Done**
- **Line format, from the POC.**
  - A time column, `yy.mm.dd hh:mm:ss`, printed only when the second changes; then a `{tag}` and the text. Further lines of one text start under its first.
  - Errors show `{!!!}`, as in the POC, and warnings show `{ ! }`, in place of the tag.
  - A line that repeats prints once, followed by `{rep} previous line repeated Nx`.
  - On a terminal the tag is colored by level: red, yellow, cyan, dim. Pipes, files, `NO_COLOR` and `TERM=dumb` get no color.
  - Tags: `{run}` for the runtime, `{gpu}` for Mechanics, `{swp}` for the swapchain, `{mod}` for recipe modules and live builds, and `{nod}` for every line about a node.
- **Levels.** They are error, warn (the default) and info, plus debug. What each one shows is written once, above `Level` in `Log.h`, and the README links to it.
- **Structure.**
  - `Log.h` still includes nothing of ours, because every recipe compiles it through `Operator.h`. `<chrono>` would add 0.45 s to each recipe build, so the header stores a `std::time_t`.
  - The writer lives in a new `Log.cpp`. It gets the local time (`localtime_r`) and `Terminal::colors()` (`isatty`) from Platform, since OS calls stay in the platform files (RA01). This is the first user of the `Terminal` placeholder.
  - The log's first line is its title, `vulpen <commit>`, printed at every level (RC07). `main` passes the title to `Runtime`. An argument error prints `vulpen <commit>: <error>` on stderr.
  - `Runtime::run` logs any failure as `{!!!}` and returns 1, so a bad manifest, a missing display or a missing GPU each end in one log line. For CPP05, `run` is split into `start`, `loop` and `watch`.
- **V09, as built.** Every line about a node uses that node's level, not only the lines its operator writes; `Schedule::log` does this. `probe` in `wave` sets `log = info`, which has two effects:
  - the default run now also prints probe's pipeline, operator and buffer lines;
  - `--log debug` hides probe's pass block, because the nearest setting wins in both directions.
