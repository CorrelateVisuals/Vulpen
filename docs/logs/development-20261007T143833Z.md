**Decisions for the lead (A00)**, each built as described, in plain words:
1. **A node knows its own name** (`node.name()`), so split can say "set my ratio". Consequence: three lines in the engine's one shared header, so every module rebuilt once. Without it, each split would need its own name written again as a param, which could go stale. Recommended: keep.
2. **A seam drag becomes one `param set`, sent when the button is let go**; the panels follow the pointer in between. Consequence: the log gains one line a drag, which a replay and a save keep, and the view rebuilds once. Sending one every frame would add about 60 lines a second to the log and rebuild every frame. Recommended: keep.
3. **One seam per split; more panels means docks inside docks.** Consequence: the manifest shows the layout as nodes and connections (V00), each seam with its own `ratio`; four panels take three docks. The other way, a whole tree in one param, would need a little language inside a param value. Recommended: keep.
4. **Split reads the pointer itself, so the dock uses no hit.** The plan had the dock as split, hit and rects. Consequence: the recipe map gives split the input and commands ports, and hit's first user is the terminal's completions. Routing the seam through hit would make a loop in the graph (split, then hit, then split), which the schedule refuses. Recommended: keep.
5. **Split paints the ground under its area** in the background color. Consequence: the empty room above the terminal shows the theme, not the black the window clears to; a dock inside a dock paints its ground again, a few full-window rectangles at most. Recommended: keep.
6. **Two words for a part's Rect**: `area` for the Rect a layout gives a part to fill (split, command-line, and viewport's output), and `place` kept for where a list's writer puts it. Consequence: no port renamed; a host wires `area` from a dock and `place` from a list's owner. Recommended: keep.
