**Why it did not shrink**
- The old drop was small because it fell short of V02: one `[deploy]` pointing at a copy whose nodes took only param edits. A copy the view owns is written as the edits a person would type, one per node and connection.
- Three features came with the restructure, each asked for that day: `recipe sync`, every node's files listed in the manifest, and the hosted views saved in it.
- The folder decides a node's files, and the manifest lists them too, so code keeps the two in step at load, after each edit and at each live scan, and warns of a folder no node names.
- The library still unfolds `recipe = <name>` at load (V11), while a view copies (V03): one way in became two.

**What it bought**
- A dropped recipe is the view's own: every edit works on it, as if built by hand (V02, V03). Before, only its params did.
- `recipe sync` takes the library's fixes into an untouched copy, keeping its params and connections. It refuses a changed copy, so a sync never overwrites a person's work.
- The manifest shows every file of every node, and a file saved in a node's folder is part of the node. `shader` is gone (V04, RV08).
- A saved project keeps the views it hosts; before, they lived only in the session's log.
- Nesting is folders, to any depth (RV08), so the POC's nest tree (875 lines, 10 verbs) stays cut.
- Two later rows cost a little less. `file rename` (D16) no longer rewrites a `shader` word, and `node duplicate` (D16) and `recipe publish` (D17) can reuse the drop's copy (C06).

**Decisions for the lead (A00)**, all from earlier handoffs and still open. Step 13 waits on the first.
1. **Native C++**: the five decisions at the end of [the proposal](../plans/native-cpp.md#decisions-for-the-lead-a00). Yes lets step 13 start: a C++ node hands another a C++ object by reference, as plain C++ does. No keeps C++ nodes exchanging only structs laid out in GLSL (D5 as first planned).
2. **The reform's seven calls** ([where the build differs](../plans/nodes-and-folders.md#where-the-build-differs-from-the-proposal)). Recommended: keep all seven.
   1. Nobody writes which shader files a node runs: the `.comp`, `.vert` and `.frag` in its folder decide. Undoing it brings back a word that lists those files twice.
   2. A node runs only the code in its own folder, so two nodes of one kind are two copies, as two drops are. Undoing it lets a node point at another folder's files, which a rename would have to rewrite.
   3. Every folder in a view is a node, even one that only holds data. A folder no node names is a warning at load, not a new node, so a removed node never comes back from its folder.
   4. When the library drops a param, a sync drops it from the copy too and names it. Undoing it makes every sync refuse once the library renames a param.
   5. `node add ui` with nothing else makes an empty group.
   6. `child remove` works from any view, also from inside the one it closes.
   7. "Recipe" now means only a library recipe: `Modules`, `nodes.cmake` and `module.so` took its other uses.
3. **Time in the frame block**: option A of the [handoff of 2026-10-03T16:18Z](development-20261003T161822Z.md) is recommended. The clock starts over each hour, so time keeps a 0.25 ms step for ever. The cost: an animation whose period does not divide an hour jumps once an hour. About 15 lines.
