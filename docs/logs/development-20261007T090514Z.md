**Decisions for the lead (A00)**, each built as described, in plain words:
1. **Roboto Mono, not DejaVu Sans Mono.** The repo holds only DejaVu Sans, which is not monospace, and the font part now refuses it. Roboto Mono was already in `assets/fonts/`, under the OFL. Consequence: text in Vulpen looks like Roboto Mono, and its license must travel with it, which it does. Recommended: keep.
2. **The font file is a copy inside the font part's folder** (87 KB), beside its license, not a path into `assets/`. A drop copies the part whole, so a project runs without the repo's `assets/` (V03). Consequence: the same file sits in the repo twice. Recommended: keep.
3. **Five roles: background, panel, border, text and accent.** Consequence: parts draw only in these colors until another is needed. Adding one takes a name in `Palette.h`, the count in `Palette.glsl` and a line in `theme.ini`. Recommended: keep, and add roles as parts need them (C00).
4. **A theme mistake stops the palette**, naming the line, as any node's error stops it. While live code runs, saving the fixed file brings it back: I checked this, since the save makes the view reload. A release build waits for the next edit of the view. Recommended: keep.
5. **Letter cells are whole pixels wide**, so glyphs land on whole pixels and stay sharp. At height 14 or 16, a faint last column of a few wide glyphs (`W`, `w`, `%`, `&`, `K`) is cut; at 18 and above, none is. Rounding up instead would keep every column but space letters wider. Recommended: keep.
