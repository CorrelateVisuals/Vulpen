**Decisions for the lead (A00)**
- **New include edge** `runtime/Commands.cpp` → `baseclasses/Platform.h`, for `Files::save`. It is in the map.
- **`--source FILE` calls the function the `source` command runs**, not the text `source FILE`, as the load calls the edits' functions (B2): a path with a blank cannot pass through the port's text until quoting exists. The file forms one group, as a typed `source FILE` would.
- **Group boundaries stay out of the file.** A replayed log forms one group, so undo after a replay would undo all of it.
- **At the top level, a relative path resolves against the working directory**, as the view and `--source` arguments do. The terminal (step 8) may want the view's folder instead.

**Open, for later steps**
- **Replay grows faster than the graph.** Building a chain of probes on the wave view, release on lavapipe:

  | Probes | Load | Replay | Replay per line |
  | --: | --: | --: | --: |
  | 25 | 0.03 s | 0.04 s | 0.8 ms |
  | 100 | 0.06 s | 0.15 s | 0.7 ms |
  | 200 | 0.08 s | 0.62 s | 1.5 ms |
  | 400 | 0.20 s | 5.47 s | 6.8 ms |

  About 85% of a replay is name comparisons in `Schedule::order`, which each rebuild runs: every connection is checked against every placed node. An index built once per call would make it linear in the connections, in about 10 lines. It needs no new structure, and it would be its own small step.
- **Edits stop at 512 nodes with pass blocks.** A rebuild holds the old blocks and the new ones at once, so a replay of 600 probes ends at its line 1022, while a load reaches 1,024.
- **A correct script prints errors.** Each rebuild between two edits reports the graph as it stands: `values reads nothing` between a `node add` and its `connect`. Replaying the 400-probe chain prints 400 such lines and exits 0.
- **No frame stamps.** A replay rebuilds the same graph (V08), and the same output (C01) only for commands that ran before the first frame, as all of step 3's do. Once the terminal (step 8) sends commands mid-run, the same output needs each group's frame in the log.
- **A live re-read of `view.vlp` is no command**, so the log stops describing the session (V06, V08). Either the log clears on a re-read, and so replays on the file as last read, or the re-read is logged as the edits that differ.
- **The log grows with every edit** (A03). That is fine for scripts. Before E7 sends a `param set` per drag frame, it needs a bound, or repeated `param set`s folded into one.
- **The migration page** still says a load runs "through the port as primitive commands"; B2 chose the edits' functions (RD02).
