**Decisions for the lead (A00)**, each built as described, in plain words:
1. **A bar's size counts text cells, not pixels**, plus 4 pixels either side. Consequence: a tab strip follows the font's size, and a side panel of `size=30` is 30 characters wide, growing with the font. Pixels would need a second param. Recommended: keep.
2. **`bar` takes all four edges now**, though only the top is used. Consequence: your "set width, not grabbable" panel is a manifest change today, for about 4 lines that nothing uses yet (C00 would wait). Recommended: keep, since you asked for it to be an option.
3. **`size=0` gives a bar no room.** Consequence: one param set hides a panel's tabs, and the content takes the strip's room. Recommended: keep.
4. **List's `rows` output is renamed `shown`**, since a tab strip's entries are not rows. Consequence: one connection in the terminal renamed; nothing else read it. Recommended: keep.
5. **The tab strip's look:** the strip in the theme's `panel` color, each tab in `background`, so it joins the content below, its label in `text`. Consequence: with one tab it reads as a title; every tab looks alike until a content has several, and the editor will need the tab it shows marked. Recommended: keep until step 21.
6. **A command-line in a window must be given `title`**; the part has no default. Consequence: a window command-line without one stops at load, naming the param; the CLI on the terminal never reads it. Recommended: keep.
7. **The tab reads `terminal - demo`**, with ` - ` between: the font draws only ASCII, and `demo:` already means a line addressed to `demo`. Recommended: keep.
