**Decisions for the lead (A00)**
- **New include edge** `runtime/Runtime.cpp` → `runtime/Edits.h`: `Runtime` owns `Edits`, at the top of the flow (A06). It is in the map.
- **The load calls the edits' functions, not the port's text.** [Migration](../architecture/migration-and-implementation.md#commands-the-engine-keeps-the-mechanism-recipes-bring-the-vocabulary) says a load runs "through the port as primitive commands"; the skeleton's edge `Manifest.cpp` → `Edits.h` says the edits themselves.
  - Calling the functions keeps the line of each word in an error, and needs no quoting for a value with a blank.
  - Both paths run the same checks.
  - The log (B3) can keep a load as the command that loaded the view.
- **`ViewLookup` changed**: `find` became const, and `replace` was added.
- **A rebuild per edit**, which a script of N edits pays N times. Ordering already grows faster than the graph (the baseline's scale row).
- **A rule for names**: node, connection, param and port names hold letters, digits, `_` and `-`, at load and at edit. A name with a dot, quote, `#` or blank could not round-trip through a manifest, an endpoint or the command line.
- **Empty values**: an empty value (`operator =`) is refused in a manifest and in `node add`. In `node set` it clears the word, and `shader` and `param` words replace all of them.
- **`node remove` refuses a connected node**, naming the connection, and `connect` refuses a cycle with a check of its own. `Schedule::order`'s cycle error is now out of reach.
- **A rebuild that throws ends the run.** That happens past the pass-block limit, or on a failed allocation, as a live swap already does. The schedule constructor moves operators, pipelines and buffers out of the old schedule as it goes, so the old one cannot run on. The CLI session (step 8) needs that to keep the running graph instead.
