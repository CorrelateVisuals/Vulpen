**Working on**: the lead asked whether the code applies const as far as it can (CPP06), and to improve it where not.

**Current problem**: none. Debug and release builds are clean with no warnings, gates are green, and `ctest` passes 3/3 in both presets. The build rewrote `LOC.md` for this tree.

**Done**
- An audit of every file under `src/` except `external-libraries/`, GLSL included. It was already strict: const locals, const getters, `constexpr` constants, and `const` in the shaders. The gaps it found are fixed:
  - Member functions that change nothing are now const: `Engine::draw`, and `Cook::read` with its `readback_bytes`. `Operator.h` changed, so the recipe stamp changes and every module rebuilds.
  - Members fixed at construction, in classes that are never copied or moved, are now const. Their default initializers went too, because every constructor sets them:
    - `Mechanics`: the instance, surface, physical device, queue family and device;
    - `_device` in `Resources`, `Pipelines` and `ShaderModule`;
    - `Swapchain`: the device, format, present mode, render pass and `_acquired`;
    - `Runtime`: `_options` and `_log`;
    - `Runtime::Live`: the folder, log file and command;
    - `_file` in the manifest `Reader`, and `_frame` in `Schedule::Cooker`.
  - Pointer locals in `Schedule.cpp` now have a top-level `const`, as `void *const` and `std::byte *const` already did elsewhere.
  - `images` in `Swapchain::make` is one const init, no longer assigned twice.
- Left out on purpose:
  - `constexpr` on Vulkan create-info structs and on small predicates. They are legal, but no work moves to compile time, which is CPP06's bar, and a CPP05 block with both `const` and `constexpr` reads worse.
  - Const members in copyable or movable types (`Log`, `Pipeline`, `PassBlock`, `Buffer`, `Library`): these swap or assign.
  - Const members that would need a new helper to be set in the initializer list: `Window::_window`, and the handles `Mechanics` makes in its constructor body.
  - `const` on by-value parameters: the codebase never writes it.
  - `Reader::name` in `Manifest.cpp`: it is assigned twice, but one const init would read worse.
- clang-format 23, from a scratchpad venv, formats some untouched lines differently from the repo, so only the hunk for my edited line was applied.
