**Decisions for the lead (A00)**, each built as described, in plain words:
1. **A new include edge**, `runtime/Schedule.cpp` → `baseclasses/Platform.h`. It brings `type_name`, which spells a C++ type in an error; that is compiler code, so it lives in the platform files. With it, a mismatch reads `std::vector<int> … but give writes a vp_mistakes::Count`; without it, `St6vectorIiSaIiEE … N11vp_mistakes5CountE`. Recommended: keep.
2. **Symbols are exported only in live builds.** The plan had it in step 1 for every build, but exporting adds 108 KiB to the release binary, and a release build links its nodes in and needs none. Recommended: keep.
3. **Windows**: a dev build's module that calls the engine by hand does not link yet, since nothing links modules against the executable there; a release build works. Untested here. Recommended: decide when a node that calls the engine is needed on Windows.
4. **Asking for room only adds room**: a buffer C++ writes always holds at least one element per invocation, so a shader that indexes by its invocation never reads past the end (GLSL02). Recommended: keep.
5. **No transfer from C++ to a shader across a connection.** It is D5's other half and was not built. A draw part's own C++ will upload what it draws from its C++ input: at step 16, `rects`, `glyphs` and `curves` each get a few lines of C++, where the recipe map lists them as shaders only, and a C++ part such as `list` hands them a `std::vector`. The other way, the engine copying a C++ vector to the GPU itself, needs more engine code and buffers that grow. Recommended: build step 16 this way, and revisit if every draw part repeats the same lines.
6. **A type only one file can name cannot be an output**: a type in an unnamed namespace would match a reader's look-alike by name and size and be read as the wrong thing. Shared types go in `contracts/`. Recommended: keep.
