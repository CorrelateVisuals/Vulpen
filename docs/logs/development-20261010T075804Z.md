**Decisions for the lead (A00)**, each built as described, in plain words:
1. **No `Offscreen` module.** The skeleton's empty `Offscreen` class could only be reached by the engine. Images draws render into take a slot in set 0, as the images C++ fills do, so they sit beside those in `Pipelines`, and no include edge is new. Saying no means new edges from the schedule and into `Pipelines`. Recommended: keep.
2. **The window opens only for a draw no connection starts from**, judged from the manifest, as before the shaders are read. A draw whose C++ also hands an object on starts a connection too, so if it is a view's only draw into the window, no window opens and it is refused loudly. No part does that today. The graph part (step 24) might, but the graph editor holds other draws into the window. Recommended: keep, and look again at step 24.
3. **`--size` has no default**: a run with no window and no `--size` renders no images, as headless runs drew nothing before. Recommended: keep.
4. **One default format, `R8G8B8A8_UNORM`**, as for images C++ fills. Its 8 bits are linear, so dark gradients band; `image = color=R8G8B8A8_SRGB` or `R16G16B16A16_SFLOAT` keeps them smooth. Recommended: keep the one default (C02), and give the Perform panel's image an sRGB word at step 23.
5. **Passes now run in graph order.** Before, every dispatch ran before every draw. Saying no means no dispatch can sample a draw's image in the frame it was drawn. Recommended: keep.
6. **Images are not kept through a rebuild**: the next frame makes them again, an image the window's size each, though they are drawn anew every frame anyway. A rebuild of the whole `ide` takes about 0.17 ms in a release build (measured below). Recommended: keep until a cost shows (C03).
