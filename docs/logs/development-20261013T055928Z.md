**Answers**
- **A, the GLSL in the graph.** A node's `.vert`, `.frag`, `.comp` and `.cpp` are its files, not nodes of their own, so the triangle is one node. Its box now lists them, and a press opens one.
- **C2, pinch.** GLFW gives no pinch event on any system. `control` with two fingers on the touchpad zooms.
- **Time in the frame block: deferred.** No restart moment suits every animation: `sin(1.3 t)` and `sin(1.7 t)` never return to their start together. An hour is seamless only for periods that divide 3600 s. A node that needs another period can loop exactly with `index % n`.
- **The seven calls of the reform**, each kept unless you say otherwise:
  1. a node's shaders are known by their extension, with no `shader` word;
  2. no node runs another node's code, so two nodes of one class are two copies;
  3. a folder that holds only data is a node too;
  4. a sync drops a param the library dropped, naming it, rather than refusing;
  5. `node add <name>` with no words makes a group;
  6. `child remove` works from any view;
  7. `Recipes` is renamed `Modules`, so "recipe" means only the library's.
- **Windows.** "Engine" there meant `VP::Engine` in `baseclasses/`, not the runtime. The runtime stays behind `Operator.h` on every platform. On Linux a node can call `baseclasses/` today; a Windows dev build does not link such a node yet.
  - The fix is to link modules against vulpen's import library, with CMake's `ENABLE_EXPORTS` and `WINDOWS_EXPORT_ALL_SYMBOLS`. The build order must change, since modules now build before vulpen.
  - It needs a Windows machine to check.
- **X, the menu bar and tab buttons.** Yes, this is in line with the plan: the menu bar and popup are later rows F6 and E15, and the tooltip and find bar are F7 and F8. Close and new-tab buttons have no row: D10 was cut, and "buttons beside a tab" was named as a possible panel layout. Recommended: a later row where a tab's Item carries a second command for its close button.
- **Y, the CLI against the POC's.**
  - The POC's `ls` walks the folder you are in: folders tagged with their node's kind, files with the kind of node that owns them, and `cd` and `pwd` to move. `ls <node>` lists a node's files.
  - Ours lists the hosted views, then `node <name>` lines and `connection <name> from … to …` lines. `info <node>` prints a node's manifest words and its connections. There is no `cd`, since folders replaced nesting (row C4, cut).
  - Recommended: make `ls` a folder tree, each node a folder with its files under it and hosted views as folders, and keep connections in `info`. About 40 lines in `inspect`.
