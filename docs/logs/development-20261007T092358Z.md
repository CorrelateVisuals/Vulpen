**Current problem**: none blocking.

**Done**
- **The font node's `face` param** names the font file it bakes: `param = face=RobotoMono-Regular.ttf` in the library's `font`.
  - It is a file of the node's folder. A face named with a folder is refused at load, naming the param (V03, A02).
  - A missing file, a file that is no font, and a font that is not monospace each stop the node, naming the face.
  - The node bakes again after every bind, so `param set font face …`, or a saved manifest, switches the face while the view runs. A bake takes about a millisecond.
- **`node.param<std::string>`**: any node's C++ may read a param as a word, which a shader never reads. This is the only engine change: three lines in `runtime/Operator.h`, so every module rebuilds once. `param` stays the one word for it, so the manifest gains none (V04, V05).

  - Roboto Mono Bold put in the folder and named;

- usage.md, the plan's E5 row and the part's manifest describe the param.
- Passing: debug 6/6, release 5/5, asan 7/7, tsan 6/6. The fail-loud test's text case reads the face from the library's manifest.

**Decisions for the lead (A00)**, each built as described, in plain words:
1. **The param is named `face`, not `font`.** The node already has a port named `font`, the one connections take as `font.font`. A param of the same name would give one node two different things called font. Consequence: you write `param = face=MyFont.ttf`. Recommended: keep.
2. **A face must be a file in the font node's own folder.** To use a font from `assets/` or from the system, copy it into that folder first. Consequence: a project still runs when moved or copied, since its fonts move with it (V03); a font cannot be shared by path. Recommended: keep.
3. **Params can now be words for C++, not only numbers.** Consequence: any part can take a file name or a choice in its manifest, as the font does, with no new word. Recommended: keep.
