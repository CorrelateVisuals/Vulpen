**Decisions for the lead (A00)**, each built as described, in plain words:
1. **The image word is written `image = atlas=R8_UNORM`**, with an `=` where the question's preview had a blank. A command's word cannot hold a blank (V06), and `node set` must be able to send the word, as it does `param = key=value`. Recommended: keep.
2. **A 16-bit float is handed as its 16 bits**, as `glm::u16vec4` and `glm::packHalf1x16` give them, since C++ must match the format exactly and C++20 has no 16-bit float. Saying no means C++ hands floats and the engine converts, the option not chosen. Recommended: keep.
3. **Two new include edges**: `runtime/Operator.h` includes glm's sized vectors (`u8vec4`, `u16vec4`), the pixels of the formats. Recommended: keep.
4. **`image clear` stays out of the log too**, as input does: it changes what the GPU holds, not the graph. So a replay does not clear an image. Recommended: keep.
5. **Input's text form takes nine commands**, such as `input key down a` and `input focus on`, not one `input <event>`. A usage's placeholders are a closed list (RV04), and `<key>` already means a param, so fixed words carry the choices. The command port then checks the number of words itself. Recommended: keep.
6. **Key names**: the character a key prints in the keyboard's layout, or a fixed name (`enter`, `left`, `f1`, `control` …). A held key repeats as more `down` events. The pointer's moves within a frame keep the last, and the pointer counts pixels, so a scaled display matches the cursor. Recommended: keep.
